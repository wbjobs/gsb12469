# IndexedDB 并发实验室

零框架、零依赖的 IndexedDB 并发行为实验台：多个**标签页**与多个 **Web Worker**
同时读写同一个 IndexedDB，可视化事务时序，并对每条并发结论给出**可核验的断言**。

## 启动

IndexedDB / Worker 在 `file://` 下行为受限，请用任意静态服务器打开：

```bash
# 任选其一
python3 -m http.server 8080
npx --yes serve .
```

浏览器访问 `http://localhost:8080/`，然后 **Ctrl/⌘ 再复制一个标签页** 打开同一地址。
每个页面自动创建 2 个 Worker（Worker A / Worker B），节点会通过
`BroadcastChannel` 自动互相发现，出现在左上角“参与节点”列表中。

## 演示场景

| 按钮 | 观察点 |
| --- | --- |
| 并发写 · 不脏读 | 一个上下文长时间持有 `readwrite` 并持续写入未提交版本；另一个上下文中的 `readonly` 事务在整个重叠期只能读到创建时快照（0）。写者提交后，新事务读到已提交值。 |
| 回滚隔离 | 写者写入大量值后 `abort()`；并发只读事务全程读不到未提交数据，回滚后库中仍是初始值，其他事务不受影响。 |
| 冲突检测 (CAS) | N 个上下文先用 `readonly` 读到同一旧版本，再用 `readwrite` 做条件写（Compare-And-Swap）。版本不匹配即中止并重试，时间轴上出现红色“冲突”中止段；最终版本恰好为 N，无丢失更新。 |
| 死锁避免 | 两个长写事务声明相同的两个 store、加锁顺序相反（AB / BA）。IndexedDB 在事务开始时**原子获取整个作用域的锁**，第二个事务在创建处排队（灰色等待段），两个事务串行完成，结构上不可能循环等待。 |
| 压力测试 | 全部标签页 + Worker 用屏障同时开始，在设定时长内批量条件递增；每批包含 `counter`、`oplog`、`data` 三个 store 的原子写。结束后从每个上下文读回数据做交叉校验。 |

### 压测校验的不变量

- `counter.n` == `oplog` 记录数 == `data.last`（无丢失、无重复）。
- 所有标签页与 Worker 读到的最终值完全一致。
- 序列号严格连续递增；每个写事务同时更新三个 store，只读快照不可能看到“撕裂”状态。

## 事务模式手动实验

左侧可手动开始 `readonly` / `readwrite` 事务：

1. 在本页开始一个 `readwrite` 事务并写入（先不要提交）。
2. 立刻在另一个标签页开始 `readonly` 事务反复读取——只能看到旧值。
3. 回到本页提交/中止，再在另一标签页开新事务——值才发生变化或完全不变。

## 时序图

Canvas 每帧重绘最近 14 秒，每个标签页 / Worker 一条泳道：

- 蓝色条：`readonly` 事务（快照隔离，可并发）。
- 橙色条：`readwrite` 事务（同 store 写锁，跨标签页/Worker 串行）。
- 灰色段：事务已创建、等待锁授权的排队时间。
- 红色条/竖线：`abort`，其中标注“冲突”的为 CAS 版本冲突中止。
- 黄色点：阶段事件（开始写入、压测进度等）。

## 实现要点

- `js/common.js`：数据库/事务封装、BroadcastChannel 总线（RPC + 控制事件 + 时间轴事件）、所有场景 Actor 与协调器。主线程和 Worker 共用同一份代码。
- `js/worker.js`：`importScripts('common.js')` 后注册同一组 Actor。
- `js/app.js`：Worker 生命周期、节点列表、日志、断言面板、手动事务、Canvas 时序图。
- 跨标签页协调全部走 `BroadcastChannel`：请求/响应（RPC）、屏障与“提交/中止”控制、事务时间轴事件。

## 验收对照

| 验收项 | 对应场景 |
| --- | --- |
| 并发写不脏读 | “并发写 · 不脏读”断言 2/3 |
| 事务冲突可检测 | “冲突检测 (CAS)”冲突中止计数 |
| 无死锁 | “死锁避免”两个事务均完成 + 排队等待 |
| 回滚不影响其他事务 | “回滚隔离”全部断言 |
| 多标签页和 Worker 一致 | 各场景跨上下文执行 + 压测交叉校验 |
| 压测结果可校验 | “压力测试”三条不变量 |
| 时序可视化准确 | Canvas 时间轴与断言数据同源 |
